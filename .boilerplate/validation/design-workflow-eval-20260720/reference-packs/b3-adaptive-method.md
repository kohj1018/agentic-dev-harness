# B3 Adaptive Hybrid Method

> Status: second-stage exploratory condition designed after the first blind evaluation. It is not part of the preregistered B0/B1/B2 comparison and requires a fresh holdout review.

## Evidence Input

- Reuse the B2 task-first packs; do not run more searches.
- Keep only task/flow evidence, one identity target, and one coherent primary implementation system.
- Do not satisfy adjacent, award, anti-pole, or token-source quotas for their own sake.

## Concept Contract

- Two concepts per brief:
  - `A / REFINE`: convention-led, with a restrained product signature.
  - `B / EXPLORE`: signature-led, while preserving the familiar task convention.
- The signature must make the primary action or choice easier to understand; a decorative rail, stepper, or motif does not qualify.
- Place required task copy, selection state, recovery/status information, and decision-time price before aesthetic elaboration.
- Use one coherent token family per concept.

## Acceptance Loop

1. Generate standalone HTML with real brief data.
2. Render at 1280x900 and 375x812; run a 320 CSS-pixel reflow check.
3. Run axe against populated content.
4. Feed concrete selectors/findings back once; do not approve while serious/critical axe findings, horizontal overflow, viewport escape, or clipped task text remain.
5. Send repaired screenshots to fresh blind holdout evaluators.

## Reason for This Condition

The first-stage result did not show an aesthetic win from broader research or stricter task-first prompting. It did show that forced signature devices could reduce coherence, and that reference quality did not prevent contrast failures. B3 therefore tests a leaner synthesis plus an explicit rendered acceptance loop.
